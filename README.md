# イコール・ラビリンス ～方程式の迷宮～

文章題を読んで、正しい方程式を立てよう！
計算はしなくてOK。数量の関係を式にできれば迷宮の扉が開く！

中学生向けの方程式文章題学習アプリです。第3段階として、中2「連立方程式」の
全12カテゴリを追加しました。中1「1次方程式」全11カテゴリと、120秒でスコア・コンボ・
段位を競う「段位認定モード」は第2段階から引き続き利用できます。分数（÷）を含む問題では、
学校の答案と同じ上下型の分数（[分数入力](#分数入力)を参照）で入力・表示できます。

## 起動方法

このアプリはJavaScriptの`import`・`export`を使用しているため、
`index.html`を直接ダブルクリックせず、必ずローカルサーバー上で実行してください。

### VS Code Live Serverでの起動方法

1. VS Codeに拡張機能「Live Server」をインストールする
2. `equal-labyrinth`フォルダをVS Codeで開く
3. `index.html`を右クリックし、「Open with Live Server」を選択する
4. ブラウザが自動的に開き、アプリが起動する

### Python簡易サーバーでの起動方法

1. ターミナルで`equal-labyrinth`フォルダに移動する

   ```bash
   cd equal-labyrinth
   ```

2. 簡易サーバーを起動する

   ```bash
   python -m http.server 8000
   ```

3. ブラウザで次を開く

   ```text
   http://localhost:8000
   ```

## ファイルごとの役割

各ファイル冒頭のコメントに役割を記載しています。大枠は次の通りです。

- **equation/** ：数式の解析・1次式／2変数1次式演算・正誤判定・表示変換。
  ゲームや問題データに依存しない独立モジュール群。`linear-expression.js`（中1・xのみ）と
  `two-variable-expression.js`（中2・x/y）は別モジュールとして分離し、`tokenizer.js`・`parser.js`は
  両方で共有する（変数トークンが`name`（"x"または"y"）を保持する形にして対応した）。
- **questions/** ：問題テンプレートの管理・出題キューの構築・生成問題の検証。
  単元による分岐は`question-manager.js`の`getTemplatesForUnit()` / `getCategoriesForUnit()`と、
  `question-validator.js`の`validateQuestion()`の数か所へ集中させている。
- **state.js** ：ゲーム状態を一元管理し、専用関数を通してのみ変更する。連立方程式用に
  `currentSystemInputTokens`（式①・式②の入力欄）・`activeSystemEquationIndex`・
  `systemCursorPositions`を追加し、専用の操作関数（`insertCharacterAtSystemCursor()`等）を用意した。
- **game.js** ：共通処理（画面遷移・数式入力・ヒント・カウントダウンなど）と、
  トレーニングモード専用の進行（固定問題数での出題・正誤処理・結果集計）を管理する。
  段位認定モード開始時は`rank-mode.js`へ処理を委譲する。単元に応じて、1本入力（中1）と
  2本入力（中2）の処理を切り替える。
- **modes/rank-mode.js** ：段位認定モード専用の進行（120秒タイマー・難易度別の無制限出題・
  スコア/コンボ反映・最終問題の猶予処理・段位計算・ハイスコア保存）を管理する。
  スコア・コンボの計算処理そのものは持たず、`rank/`配下の純粋関数を呼び出す。
- **rank/score-manager.js / combo-manager.js / rank-calculator.js** ：
  DOM・タイマーを持たない純粋な計算モジュール。スコア加減点、コンボとコンボゲージの状態遷移、
  段位係数・段位名の計算だけを担当し、単体でテストできる。基準時間（timeB）は呼び出し側
  （`rank-mode.js`）が単元ごとに`UNIT_CONFIG`から取得して渡す。
- **ui.js** ：DOM操作専用。ゲームルールや正誤判定は書かない。
- **timer.js / audio.js / storage.js** ：それぞれ問題ごとの時間計測（ヒント・パス解禁）・
  効果音・保存を専任で担当する。段位認定モードの120秒タイマーは`rank-mode.js`が別途管理する
  （詳細は「タイマー構成」を参照）。

## 正誤判定の仕組み（中1「1次方程式」）

1. `tokenizer.js`が入力文字列をトークン列へ分解する（暗黙の乗法を自動補完）。
2. `parser.js`が優先順位（かっこ→単項マイナス→乗除→加減）に従ってASTを構築する。
   `eval()`や`Function()`は使用していない。
3. `equation-validator.js`が「＝」の数・両辺の空チェック・左右の構造（`x=4`のような
   答え直接入力の排除）を確認したうえで、左辺と右辺をそれぞれ`linear-expression.js`の
   `astToLinearExpression()`で1次式 `{ xCoefficient, constant }` に変換する。
4. 左辺－右辺を計算し、`ax + b = 0`の形に整理する。
5. `a === 0`の場合は、恒等式または解なしとして不正解にする。
6. `a !== 0`の場合は`x = -b / a`を計算し、問題データの`expectedX`と
   （`config.js`の`numericTolerance`の範囲で）比較して正解・不正解を判定する。

模範式との文字列完全一致では判定していないため、
`150x+80(10-x)=1080`と`80(10-x)+150x=1080`のように、
同じ数量関係を表す異なる式もすべて正解になる。

## 連立方程式の正誤判定（中2「連立方程式」）

連立方程式では、(x, y)の解が一致するだけでは正解にしない。文章題は
**2つの数量関係を立式する力**を確認するアプリのため、入力された式①・式②のそれぞれが、
問題データに登録された`canonicalEquations`（2本の模範関係）のいずれかと
「0でない定数倍」の関係にあるかどうかで判定する（`system-equation-validator.js`）。

### 各入力式の標準化

入力された1本の方程式について、`two-variable-expression.js`の
`astToTwoVariableExpression()`で左辺・右辺をそれぞれ2変数1次式
`{ xCoefficient, yCoefficient, constant }`に変換し、左辺－右辺を計算して
`ax + by + c = 0`の標準形（`system-equation-validator.js`の`parseEquationToStandardForm()`）にする。

- `xCoefficient === 0 && yCoefficient === 0 && constant === 0`（恒等式、例：`x+y=x+y`）→不正解
- `xCoefficient === 0 && yCoefficient === 0 && constant !== 0`（解なし、例：`x+y=x+y+1`）→不正解

### 模範関係との同値判定

`areProportionalEquations()`が、入力式の係数`[a, b, c]`と模範関係の係数`[A, B, C]`が
0でない定数倍かどうかを判定する。

1. 模範式の係数のうち、絶対値が最も大きいものを基準にする
2. 入力式との倍率を求める
3. 3つの係数がすべて同じ倍率か、`numericTolerance`の範囲内で確認する
4. 倍率が0の場合は不正解

式①・式②の順番は問わない。入力式①が模範式①・②のどちらと一致してもよいが、
式①・式②がそれぞれ別の模範関係と1対1で対応する場合のみ正解にする
（`matchesInOrder` / `matchesSwapped`のいずれかがtrueになる場合）。そのため、

- `x+y=10`と`2x+2y=20`（同じ関係を2回入力）→どちらも模範式①にしか一致しないため不正解
- `x+y=10`と`30y=120`（2本の模範式から消去法で導いた式）→模範式のどちらにも一致しないため不正解

のように、数学的に解ける・同じ解を持つだけの式は正解にならない。

### 別解（alternateEquations）

同じ立式であっても、文章題を「増減後の合計」に着目して立てるか「変化量」に着目して
立てるかで、教育的に自然な式が2通り以上ある問題がある（例：「割合の増減・人数」
「割合の増減・代金」）。このような場合、問題データに`alternateEquations`
（`{index, internal, display, relationName}`の配列。`index`は`canonicalEquations`の
どちらのスロットの別解かを表す）を追加すると、そのスロットは`canonicalEquations[index]`
「または」`alternateEquations`のいずれかと定数倍の関係にあれば正解として扱われる
（`system-equation-validator.js`の`buildAcceptableExpressionsBySlot()`）。

```javascript
canonicalEquations: [
  { internal: "x+y=140", display: "x＋y＝140", relationName: "昨年の人数の合計" },
  { internal: "1.1*x+0.95*y=148", display: "1.1x＋0.95y＝148", relationName: "今年の人数の合計" }
],
alternateEquations: [
  {
    index: 1,
    internal: "0.1*x-0.05*y=8",
    display: "0.1x－0.05y＝8",
    relationName: "人数の変化量の関係"
  }
]
```

ただし、式①・式②の両方を別解（またはその両方を模範式）で埋めることはできない。
必ず一方が`canonicalEquations`の一方、もう一方が残りのスロット（模範式または
そのスロットの別解）と1対1で対応する必要がある（＝2つの独立した数量関係を
表現しているかどうかという判定方針自体は変わらない）。

### 解の確認（念のための追加チェック）

各式が模範関係と一致したうえで、`solveTwoVariableSystem()`が実際にクラメルの公式で
入力式を解き、`expectedSolution.x` / `.y`と一致することも確認する
（行列式が0＝2本の式が独立していない場合は不正解）。これは問題データや比較処理の
不具合を検出するための追加の安全策であり、通常の判定は模範関係との同値判定だけで完結する。

## 数式キーボードの仕様

数字を1桁ずつ入力する負担を減らすため、固定の`0`〜`9`・`.`キーは廃止し、
**その問題で方程式を立てるために必要な数値を、完成した数値のままボタンとして表示する方式**にしている。

### 問題データに追加した2つのプロパティ

```javascript
keypadNumbers: ["1100", "400", "15", "9500"], // 数値ボタン（問題文に登場する順、文字列で管理）
keypadSymbols: ["x", "+", "-", "(", ")", "="]  // その問題に必要な記号だけを指定する
```

- `keypadNumbers`は数値を**文字列**で管理する（将来の小数`"0.8"`や分数`"1/2"`にも対応できるようにするため）。
- `keypadNumbers`は、方程式を解いた答え（`expectedX`）そのものではなく、
  **模範方程式を組み立てるために必要な数値**を、問題文に登場する順に登録する。
- 重複する数値は1つだけ登録すればよい（`ui.js`側でも重複を除去してから描画する）。
- `keypadSymbols`に含まれる記号だけがキーボードに表示される。表示順は配列の記述順ではなく、
  `ui.js`内の`SYMBOL_ORDER`（x → y → x² → + → − → × → fraction → ( → ) → =）という統一順に従う
  （x²は今回まだ使用しない）。
- 分数（割り算）を含む問題では、`÷`の代わりに`"fraction"`を`keypadSymbols`へ指定する。
  詳細は「分数入力」を参照。
- 乗法記号を省略した式（`120x`など）を入力する問題では、`×`を`keypadSymbols`へ含める必要はない。
  数値の直後に`x`や`(`を入力すると、既存の数式解析（`tokenizer.js`の暗黙の乗法補完）がそのまま処理する。

### 描画とキー操作

- `ui.js`の`renderEquationKeypad(question)`が、現在の問題データから数値キー・記号キーを
  再描画する。前の問題のボタンが残らないよう、`game.js`は問題が切り替わるたびに必ずこれを呼び出す。
- 数値ボタンを1回押すと、その数値全体（例：`"1100"`）が1つの入力トークンとしてカーソル位置へ
  挿入される。入力状態は`state.js`の`currentInputTokens`配列で管理しており、配列の1要素が
  数値ボタン1回分の入力に対応するため、桁の途中にカーソルを置いたり、1文字ずつしか消せなかったり
  することはない。左右カーソル・1つ消す・全消去は、この配列の要素単位でそのまま動作する。
- PCの物理キーボードからは、引き続き数字を1桁ずつ入力できる（アクセシビリティのフォールバック）。
  この経路で入力された式も、既存の数式解析処理でそのまま正誤判定できる。

### フォールバック

`keypadNumbers`が未設定のままの問題データが渡された場合でも、アプリが停止しないよう、
`question-manager.js`の`ensureKeypadNumbers()`が`canonicalEquation`から数値を自動抽出して補い、
コンソールに次のような警告を表示する。

```text
問題 L1-01-001 にkeypadNumbersが設定されていません。canonicalEquationから数値を自動抽出しました。
```

ただし、これはあくまで保険であり、正式な問題テンプレートでは必ず`keypadNumbers`を明示すること。

## 分数入力

速さ・道のりの問題（`x÷8`など）を、`x÷8`という横並びの表記ではなく、学校の答案と同じ
上下型の分数（分子・分数線・分母）で入力・表示できる。

### 基本の操作

```text
x → 分数 → 8
```

と入力すると、画面上には

```text
x
─
8
```

のように上下型で表示される。分数ボタンを押すと、直前の1トークン（`x`・`y`・数値・
ヒント式パーツのいずれか）が分子になり、分母が空欄の「分母入力待ち」状態になる。
続けて数値ボタン（例：`8`）を1回押すと、その数値がそのまま分母になり、分数が完成する。
分母入力待ちの間は、入力欄付近に「分母を選んでください。」という案内
（`#input-guidance`、`aria-live="polite"`）が表示される。

### 内部表現と画面表示の分離

- 画面表示：`js/equation/equation-formatter.js`の`renderFormattedEquation()`が、
  内部表現の文字列（`x/8`など）をトークナイザーで解析し、`/`のパターンを見つけた箇所だけを
  `.math-fraction`（分子・分数線・分母のDOM）として描画する。入力欄・正解表示・履歴・
  ヒント式パーツのすべてで、この関数を共通利用する。
- 正誤判定：分数トークンは`js/state.js`の`serializeFractionToken()`によって
  `((分子)/(分母))`という文字列へ変換され、既存の数式パーサー（`/`＝定数除算）へそのまま渡される。
  数式パーサー・正誤判定ロジック自体は変更していない。

### 分数トークンのデータ構造

入力欄のトークン列（`state.js`の`currentInputTokens` / `currentSystemInputTokens[i]`）は、
これまで「1文字、またはヒントパーツ1つ」を表す文字列の配列だったが、分数はその配列の中に
次のオブジェクトとして1要素挿入される（完成した分数は、削除・カーソル移動の単位として
1トークン扱いになる）。

```javascript
{
  type: "fraction",
  numeratorTokens: ["x"],      // 分子（現時点では常に1要素）
  denominatorTokens: ["8"],    // 分母（分母入力待ち中は空配列）
  isComplete: true
}
```

### 今回対応する範囲

- 分子：`x`・`y`・1つの数値・1つのヒント式パーツ
- 分母：1つの数値（キーボードの数値ボタンを1回押すと確定する）
- 分母が0になる入力は拒否する（「分母に0は使えません。」）
- 分子として使えないもの（空欄・`+`・`−`・`×`・`=`・かっこ・分数）の直後で分数ボタンを押しても、
  分数は作られない（「先に分子を入力してください。」）
- 分母入力待ち中は、数値以外のキー（`x`・`y`・演算子・かっこ・別の分数ボタン・ヒントパーツ）を
  受け付けない（「分母には数値を入力してください。」）。「1つ消す」だけは、分数の作成を取り消して
  分子（例：`x`）へ戻すために使える
- 分母入力待ちの分数がある間は、解答ボタンが無効になり、連立方程式では式①・式②の切り替えも
  できない（「先に分母を入力してください。」）
- `x+y`のように複数項をまとめて分子・分母にする分数（`(x+y)/2`など）の手入力には、今回は対応していない

### 問題データでの指定方法

```javascript
keypadNumbers: ["14", "8", "6", "2"],
keypadSymbols: ["x", "y", "+", "fraction", "="], // ÷ではなくfractionを指定する

canonicalEquations: [
  { internal: "x+y=14", display: "x＋y＝14" },
  { internal: "x/8+y/6=2", display: "x/8＋y/6＝2" } // internalは従来どおり"/"を使う
]
```

`hintKeypadParts`にも、分数専用の形式を追加できる。

```javascript
hintKeypadParts: [
  {
    type: "fraction",
    display: "x/8",
    value: "x/8",
    numerator: "x",
    denominator: "8",
    ariaLabel: "8分のx"
  }
]
```

このヒントパーツを押すと、完成済みの分数トークンが1回の操作でカーソル位置へ挿入される。

### 既存データとの後方互換

`keypadSymbols`に旧仕様の`"÷"`または`"/"`が残っていても、`ui.js`の`normalizeKeypadSymbol()`が
表示直前に`"fraction"`へ自動変換し、コンソールへ警告を出す（アプリは停止しない）。
正式な問題テンプレートは、順次`"fraction"`へ書き換えること。

## ヒント式パーツ

通常時は生徒自身に数量関係を考えさせ、ヒントボタンを押して困ったときだけ、
文章中の「1つの数量を文字で表す部分」をボタンとして与える機能。

### 問題データに追加したプロパティ

```javascript
hintKeypadParts: [
  {
    display: "（15−x）",  // キーボードに表示する文字列
    value: "(15-x)",       // 押したときに入力欄へ挿入される文字列
    ariaLabel: "15ひくx"   // スクリーンリーダー向けの読み上げ用ラベル
  }
]
```

- ヒントボタンを押すと、`hint`のヒント文と同時に`hintKeypadParts`がキーボードへ追加される
  （`ui.js`の`renderHintKeypadParts()`）。数値ボタンと同様、1回押すと`value`全体が
  1つの入力トークンとしてカーソル位置へ挿入されるため、パーツ単位で削除・移動できる。
- 式パーツが不要な問題（`x`をそのまま使うだけの基本問題など）では、空配列`hintKeypadParts: []`
  を設定する。この場合、ヒントボタンを押してもヒント文だけが表示され、式パーツ領域は表示されない。
- ヒントボタンを複数回押しても、式パーツが重複して追加されることはない
  （`game.js`の`currentQuestionHintUsed`フラグで最初の1回だけ公開する）。
- 問題が切り替わる（次の問題・パス後・リトライ後・タイトルへ戻った後）たびに、
  式パーツ領域は必ずクリアされ、前の問題のパーツは残らない。
- `type: "fraction"`を指定すると、上下型分数の見た目のボタンになり、押したときに
  完成済みの分数トークンが1回の操作で挿入される（分子・分母を個別に押す必要はない）。
  詳細は「分数入力」を参照。

### 式パーツの設定基準

- **1問につき原則1個、多くても2個まで**にする。複数の数量表現がある場合は、
  最もつまずきやすいものだけを選ぶ。
- 式パーツは「1つの数量を文字で表した部分」に限定する（例：`(15-x)`、`(x+10)`）。
  `400(15-x)`や`1100x+400(15-x)=9500`のように、項全体・式全体を与えると
  立式の学習効果が失われるため設定しない。
- `x`をそのまま使うだけの問題（個数・代金の基本問題など）には、無理に式パーツを設定しない。

### 検証とフォールバック

`question-validator.js`が、`hintKeypadParts`の各要素について次を確認する。

- 配列であること（空配列は許可する）
- 各要素が`display`・`value`を持つオブジェクトであること
- `value`が既存の数式トークナイザ（`tokenizer.js`）で解析できる文字列であること
- `value`に`＝`が含まれていない（完成した方程式全体を登録していない）こと

`hintKeypadParts`が未設定の問題データが渡された場合でも、`question-manager.js`の
`ensureHintKeypadParts()`が空配列として扱い、アプリは停止しない
（コンソールに警告を表示するのみで、式パーツの自動生成は行わない）。

### 結果画面での記録

問題履歴には、次の3項目を区別して記録する。

- `hintUsed` … ヒントボタンを押したか
- `hintPartsRevealed` … 式パーツが実際にキーボードへ表示されたか（`hintKeypadParts`が空の問題では常に`false`）
- `hintPartUsed` / `usedHintPartValues` … 表示された式パーツを実際に押して入力したか、その内容

結果画面には「ヒント：使用／未使用」「式パーツ：使用／未使用／未表示」として表示される。
MVPでは、ヒントや式パーツの使用によるスコア・段位への減点は行わない。

## 段位認定モードの遊び方

タイトル画面で「段位認定」を選ぶと、問題数・カテゴリの代わりに単元（1次方程式／連立方程式）と
難易度（NORMAL／HARD）の選択が表示される。スタートすると120秒のカウントダウンが始まり、
時間が尽きるまで文章題に次々と解答する。正解数・解答時間・ミス・パスの回数から、
「皆伝」〜「10級」までの段位が認定される。

> 120秒以内に、できるだけ多くの方程式を立てよう！
> 正解数・解答時間・ミス・パスから段位を認定します。

ヒント・パス・数式キーボードなど、基本的な操作方法はトレーニングモードと共通。
連立方程式を選んだ場合は、式①・式②の2本を入力する（詳細は「連立方程式の入力画面」を参照）。

## NORMAL・HARDの違い

中1「1次方程式」は`js/questions/linear/categories.js`の`LINEAR_CATEGORIES`、
中2「連立方程式」は`js/questions/simultaneous/categories.js`の`SIMULTANEOUS_CATEGORIES`で、
カテゴリごとに`difficulty: "NORMAL"`または`"HARD"`を設定している。

### 中1「1次方程式」

| 難易度 | 出題されるカテゴリ |
| --- | --- |
| NORMAL | 個数・代金／分配・過不足／年齢／追いつき・出会い／2種類の品物と代金／大人・子どもの人数と料金 |
| HARD | 所持金・過不足／長いす・過不足／整数／速さ・時間・道のり／割合・増減 |

### 中2「連立方程式」

| 難易度 | 出題されるカテゴリ |
| --- | --- |
| NORMAL | 2種類の品物と代金／人数と料金／硬貨・紙幣／年齢／速さ・道のり／食塩水の混合 |
| HARD | 2けたの自然数／電車の通過／池・トラックの周回／割合の増減・人数／割合の増減・代金／平均 |

段位認定モードでは、選んだ単元・難易度に属するカテゴリだけから出題される
（`question-manager.js`の`getNextRankQuestion(unit, difficulty, ...)`）。トレーニングモードでは、
難易度に関わらず、選んだ単元の全カテゴリを選択できる。

## スコア計算（`js/rank/score-manager.js`）

- 正解時：`1000 + 100 × 正解後のコンボ数`を加算する（1コンボ目の正解で＋1100、2コンボ目で＋1200…）
- 不正解時：`-300`を減点する（入力エラーは減点しない）
- パス時：`-500`を減点する。加えて正解点を得られず、コンボがリセットされ、段位係数に＋4される
- スコアは0点未満（マイナス）を許可する
- 画面上のスコア表示は、内部の正式なスコア（即座に更新される）とは別に、
  `ui.js`の`animateScoreTo()`が現在値から目標値へ約0.5秒かけてドラムロール風に変化させる。
  連続して判定が発生した場合は、直前のアニメーションを打ち切って新しい目標値へ描画し直すため、
  表示上の数値がずれることはない

## コンボ計算（`js/rank/combo-manager.js`）

- コンボ継続ゲージが残っている間に正解すると、コンボが1増える
- ゲーム開始後の最初の問題、パス直後の問題、ゲージが0になった直後の問題では、
  ゲージを減少させない（`comboBuildPending`状態）。この状態で正解すると「1 COMBO」から始まる
- ゲージが0になった瞬間に、現在のコンボを0へ戻す（不正解しただけでは即座にリセットしない）
- パスすると、コンボとゲージが0にリセットされる
- 最大コンボ数（`maxCombo`）は、セッションを通じて記録され続ける

## コンボ継続ゲージ計算

単元ごとの基準時間`timeB`を`js/config.js`の`UNIT_CONFIG[unit].baseTimeSeconds`から取得し
（1次方程式＝12秒、連立方程式＝20秒）、ゲージの基本継続時間を`timeB × 2`とする。
現在のコンボ数を`n`とすると、ゲージの減少速度は`1 + 0.05n`倍になり、
実際にゲージが空になるまでの時間は`(timeB × 2) ÷ (1 + 0.05n)`秒になる。
この計算式自体は単元によらず共通で、`js/rank/combo-manager.js`の`createComboState(baseTimeSeconds)`が
`baseTimeSeconds`をコンボ状態に保持し、`gaugeDurationForCombo()`へ渡すことで単元ごとの
基準時間を反映している。

### 1次方程式（基本継続時間24秒）

| コンボ数 | ゲージ継続時間 |
| ---: | ---: |
| 1 | 約22.86秒 |
| 2 | 約21.82秒 |
| 3 | 約20.87秒 |
| 5 | 19.20秒 |
| 10 | 16.00秒 |

### 連立方程式（基本継続時間40秒）

| コンボ数 | ゲージ継続時間 |
| ---: | ---: |
| 1 | 約38.10秒 |
| 2 | 約36.36秒 |
| 3 | 約34.78秒 |
| 5 | 32.00秒 |
| 10 | 約26.67秒 |

正解すると、次の問題が始まった時点でゲージが100％から動き出す（正解した瞬間ではない）。
正解演出（約2秒）の間は全体タイマーとコンボゲージの両方を一時停止し、次の問題が表示された
時点で再開することで、演出中に不当にゲージが減ることを防いでいる。

## 段位計算（`js/rank/rank-calculator.js`）

正解した問題の解答時間の平均を`timeA`、基準時間`timeB`（`UNIT_CONFIG[unit].baseTimeSeconds`。
1次方程式は12秒、連立方程式は20秒）として、次の式で基本段位係数を計算する（小数点以下切り上げ）。

```javascript
const baseCoefficient = Math.ceil(
  Math.sqrt((timeA / timeB) * 400) - 20
);
```

基本段位係数へ、次の補正を加算する。

| 条件 | 加算値 |
| --- | ---: |
| 不正解1回につき | ＋1 |
| パス1回につき | ＋4 |
| 最終問題が時間切れ | ＋2 |
| 正解数が2問 | ＋3 |
| 正解数が1問 | ＋10 |
| 正解数が0問 | ＋20 |

正解数による補正は重複させない（2問なら＋3のみ、1問なら＋10のみ）。補正後の段位係数は
0〜20の範囲に収め、正解数が0問の場合は必ず最終係数20（10級）になる。段位係数は、
0（皆伝）〜20（10級）の21段階に対応する段位名（皆伝・十段・九段・八段・七段・六段・五段・
四段・三段・二段・初段・1級〜10級）に変換される。HARDモードでは、段位名の末尾に「＋」を
付ける（例：三段＋）。

## ハイスコア保存形式

`localStorage`へ、単元・難易度の組み合わせごとに保存する（`storage.js`の
`saveRankHighScore()` / `loadRankHighScore()`）。

```text
equalLabyrinth.rank.linear.NORMAL
equalLabyrinth.rank.linear.HARD
equalLabyrinth.rank.simultaneous.NORMAL
equalLabyrinth.rank.simultaneous.HARD
```

```javascript
{
  highScore: 24500,
  bestRankCoefficient: 4,
  bestRankName: "七段",
  maxCorrectCount: 12,
  maxCombo: 8,
  updatedAt: "2026-07-19T00:00:00.000Z"
}
```

- スコアは、保存済みハイスコアを上回った場合にのみ更新する
- 最高段位は、段位係数が小さいほど上位として扱う（例：三段＝係数8よりも五段＝係数6のほうが上）
- スコアの記録と段位の記録は、それぞれ独立して更新される
- `localStorage`への保存に失敗しても（プライベートブラウジング等）、アプリは停止しない

## タイマー構成

次の7種類のタイマーを、それぞれ独立して管理している（`js/timer.js`と`js/modes/rank-mode.js`）。

1. 全体制限時間（120秒、`rank-mode.js`が`setInterval`のポーリングと`performance.now()`の
   差分で管理。正解演出中は一時停止する）
2. 問題ごとの解答時間（`timer.js`。モードに関わらず共通）
3. ヒント解禁時間（段位認定モードのみ20秒、`timer.js`。トレーニングモードでは
   `game.js`の`beginQuestion()`が出題直後に即座に解禁する）
4. パス解禁時間（段位認定モードのみ40秒、`timer.js`。トレーニングモードでは
   ヒントと同様に出題直後から使用できる）
5. コンボ継続ゲージ（`combo-manager.js`が絶対時刻ベースで管理。全体タイマーの一時停止中は、
   停止していた時間だけ基準時刻をずらして補正する）
6. 残り時間0秒後の30秒猶予（`rank-mode.js`が全体タイマーとは別に管理する）
7. 正解・パス表示（トレーニング：「次へ」ボタンを押すまで表示し続ける。
   段位認定：正解は約2秒間、パスは約1.5秒間で自動的に次の問題へ進む）

リトライ・タイトルへ戻る操作では、`game.js`が`timer.stopQuestionTimer()`と
`rankMode.stopRankSession()`（段位認定モードの場合）の両方を呼び出し、すべてのタイマーを
確実に停止させる。

## 問題テンプレートの追加方法

中1「1次方程式」（`js/questions/linear/`）・中2「連立方程式」（`js/questions/simultaneous/`）
どちらも同じ手順で追加できる。以下は1次方程式を例にする（連立方程式の場合は
`expectedX`→`expectedSolution: {x, y}`、`canonicalEquation`（文字列1本）→
`canonicalEquations`（`{internal, display, relationName}`の配列2本）、
`displayEquation`は使わない、という対応関係になる）。

1. 対象カテゴリのJSファイルを開く（例：`js/questions/linear/price-basic.js`、
   連立方程式なら`js/questions/simultaneous/two-products.js`）
2. テンプレートオブジェクトを配列へ追加する
3. 一意の`templateId`を設定する（他のテンプレートと重複しない文字列）
4. `generate()`関数を実装し、必須項目をすべて返すようにする
   - 1次方程式：`expectedX`・`canonicalEquation`・`displayEquation`・`prompt`・`hint`・`explanation`など
   - 連立方程式：`expectedSolution`・`canonicalEquations`（2本）・`variableDefinitions`（x・y）・
     `solutionDisplay`・`prompt`・`hint`・`explanation`など
5. `rankDifficulty`に、そのカテゴリの難易度（`"NORMAL"`または`"HARD"`）を設定する。
   `categories.js`の`LINEAR_CATEGORIES`／`SIMULTANEOUS_CATEGORIES`に登録した難易度と
   一致しないと、`question-validator.js`が不正な問題として除外する
6. `keypadNumbers`（問題文に登場する順の数値の配列、文字列で管理）と、
   `keypadSymbols`（その問題に必要な記号だけの配列。連立方程式は`x`・`y`・`=`を含める）を設定する
7. 問題データの必須項目が欠けていないか確認する
8. 1次方程式では`expectedX`と`canonicalEquation`を解いた結果が、連立方程式では
   `expectedSolution`と`canonicalEquations`（2本の連立方程式として解いた結果）が
   一致することを確認する（`question-validator.js`が自動検証するが、手計算でも確認する）
9. 式に登場する定数（係数1・負号で作られる負の数などを除く）が、すべて`keypadNumbers`から
   入力できることを確認する（これも`question-validator.js`が検証する）
10. 連立方程式の場合、2本の`canonicalEquations`が互いに定数倍の関係（比例）にならないこと
    （＝連立方程式として独立であること）を確認する。生成する数値に依存関係があると、
    まれに2本が比例してしまい解けない問題になることがあるため、必要に応じて
    `while`ループなどで値の重複・比例を避けるガードを入れる
    （`price-discount.js`・`train-passage.js`に実例がある）
11. `hintKeypadParts`を設定する場合は、次を確認する
    - ヒント文と式パーツの内容が一致しているか
    - 式パーツが完成式に近くなりすぎていないか
    - 1つの数量だけを表すパーツになっているか（1問につき1〜2個まで）
    - 式パーツを使って模範式を入力できるか
    - 式パーツを使わなくても問題を解けるか
    - 式パーツがなくてもよい問題では`hintKeypadParts: []`になっているか
    - 連立方程式では、ヒント式パーツは現在アクティブな式（式①または式②）にのみ挿入される
12. ローカルサーバーでブラウザから起動し、実際に出題されることと、
    意図した数値ボタン・記号ボタン・ヒント式パーツだけが表示されることを確認する

## カテゴリ難易度の設定方法

カテゴリの難易度は、単元ごとの`categories.js`1か所（`LINEAR_CATEGORIES`／

検証エラーとして出題対象から除外する（`question-manager.js`のフォールバック問題にも、
同様に一致した`rankDifficulty`を設定している）。

## 既知の制約

- 効果音はWeb Audio APIによる単純な生成音であり、外部音声ファイルは使用していない
- 中3「2次方程式」単元は画面上「準備中」と表示されるのみで、今回の第3段階では
  選択・操作できない（`UNIT_CONFIG`に`baseTimeSeconds: 14`のエントリだけ先行して用意してあるが、
  `SELECTABLE_UNIT_IDS`には含めていない）
- 除算は分母が定数の場合のみ許可しており、`1/2x`・`x/y`・`x/(x+1)`のような
  変数を含む・非1次の除算は入力エラーになる
- 数式入力は半角・全角の演算記号（`×÷−`など）と`*` `/` `-`の両方を認識するが、
  全角数字（１２３など）には対応していない
- 数式キーボードの数値ボタンは、各問題テンプレートの`keypadNumbers`に明示された数値のみを表示する
  （問題文からの自動抽出は、`keypadNumbers`未設定時の保険としてのみ動作する）
- 分数入力（上下型分数）は、分子・分母がそれぞれ1トークン（`x`・`y`・1つの数値・
  1つのヒント式パーツ）の単純な分数のみに対応する。`(x+y)/2`のような複数項を
  手入力でまとめて分子・分母にする操作には対応していない（詳細は「分数入力」を参照）
- 分母入力待ち中の物理キーボード対応は最小限で、数値ボタン（1回押しで分母全体が確定）が
  基本の操作方法。物理キーボードで分母の数字キーを押した場合は、押した1文字がそのまま
  分母として確定する（`1`→`0`と押しても`10`にはならない）ため、2桁以上の分母は
  画面上の数値ボタンで入力すること
- 段位認定モードのハイスコアはブラウザの`localStorage`に保存され、端末・ブラウザをまたいだ
  同期やオンラインランキングには対応していない
- 段位認定モードの全体タイマー・コンボゲージは、タブが非アクティブになっている間も
  `performance.now()`との差分で経過時間を計算するが、ブラウザがバックグラウンドタブの
  `setInterval`実行間隔を大きく間引く場合、残り時間の表示更新がまとめて反映されることがある
  （時間切れなどの判定自体は、次にタブがアクティブになった時点で正しい経過時間により行われる）
- 連立方程式の`xy`・`x(x+1)`・`(x+y)(x-y)`のような、少なくとも一方が定数でない項どうしの
  乗除は、`two-variable-expression.js`が非線形として入力エラーにする（中2の範囲を超えるため、
  対応する必要がない）
- 連立方程式の正誤判定は「入力式が2本の`canonicalEquations`のいずれかの0でない定数倍になっているか」
  を式①・式②の入れ替えを含めて判定する方式であり、(x, y)の解自体が一致していても、
  文章題の数量関係を表さない式（消去法で導出した式や無関係な式）は不正解として扱う。
  この判定は文字列比較ではなく標準形（`ax+by+c=0`）への変換と比例判定によって行っているため、
  項の順序や係数の書き方の違い（`x+y=10`と`y+x=10`など）は正しく同一視される
- 解答ボタンの有効化条件（両辺非空・必要な変数を含む・＝が1つ等）はUI側（ボタンの`disabled`属性）
  でのみ判定しており、`handleSubmit()`自身は構造的妥当性を事前に再チェックしていない。
  ただし、無効化された`<button disabled>`はクリックしてもイベントが発火しないため、
  通常のユーザー操作でこの制約が問題になることはない（1次方程式でも同じ設計）
